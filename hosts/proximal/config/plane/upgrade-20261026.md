# Plane CE upgrade — 2026-10-26

The owner requested an upgrade and summarized changelog after confirming both
instances still ran their original v1.3.1 images from June. Upgraded the internal
`plane-app` and public `plane-harm-org` application services to v1.4.2, the latest
Community Edition release returned by GitHub on the upgrade date.

## Release and configuration review

Compared upstream v1.3.1 and v1.4.2 Compose and environment templates. Adopted
the new application images and explicit authentication throttle. Kept the
existing bundled private PostgreSQL/Valkey/RabbitMQ/MinIO containers and public
PostgreSQL 17/Redis/Garage/RabbitMQ arrangement. Upstream's switch to a different
MinIO image was not part of this application upgrade; the existing private
MinIO image and volumes remain. Proxy binds remain loopback-only.

The private instance used the upstream's published default `SECRET_KEY` and an
empty `LIVE_SERVER_SECRET_KEY` that selected a public Compose fallback. Generated
both secrets in its mode-0600 `plane.env` and recreated the application services.
The public instance already had generated secrets, which were preserved.
Removed secret defaults from the newly captured private canonical Compose;
materializing its effective database/queue DSNs in the private env file preserved
the resolved service configuration exactly. No credential values enter Git.

## Backups and migration

Private backup root, mode 0700, outside Git:
`~/.local/share/infra/backups/plane-20261026-v1.3.1/`.

Each `plane-selfhost/` and `plane-harm-org/` subdirectory contains its original
`plane.env`, Compose file, PostgreSQL custom-format `database.dump`, archive
contents listing, and `objects.tar`. Files are mode 0600. The private object
backup contains 33 objects (1,639,772 source bytes); the public bucket is empty.
Objects were copied before stopping application services; database dumps were
taken after stopping each instance's application writers.

Both dumps restored with `pg_restore --exit-on-error --no-owner --no-acl` into
temporary PostgreSQL 17 databases. Project and work-item counts matched; the
temporary databases were then dropped. The private source remains PostgreSQL 15;
this backup check did not migrate it to the host database.

Ran v1.4.2's migrator separately before starting the new app containers. Both
instances successfully applied `db.0122_alter_draftissue_assignees_alter_issue_assignees_and_more`
and `django_celery_beat.0019_alter_periodictasks_options`. App services were
recreated with `--no-deps --pull never` using the pre-pulled v1.4.2 images.

For rollback, stop the affected app services, restore that instance's original
configuration and matching database dump, then start its retained v1.3.1 images.
Take a fresh backup first if writes have resumed: restoring the pre-upgrade dump
discards subsequent writes. Do not merely downgrade images against a migrated
database. Object storage was not migrated or replaced.

## Summarized upstream changes

- [v1.4.0](https://github.com/makeplane/plane/releases/tag/v1.4.0): lighter list
  APIs; workspace slug in webhooks; bounded database log retention; broad access
  control, authentication, invitation, XSS, SSRF and API-token hardening; fixes
  for notifications, project membership, deleted states, timestamps and Safari.
- [v1.4.1](https://github.com/makeplane/plane/releases/tag/v1.4.1): administrator
  command to reactivate workspace members; better module membership/filtering;
  UI error isolation; fixes for notifications, missing labels, empty responses
  and export refresh; upload-limit enforcement and dependency security updates.
- [v1.4.2](https://github.com/makeplane/plane/releases/tag/v1.4.2): automatic
  recovery when navigation encounters an outdated JavaScript chunk.
