# PostgreSQL 17.11 activation — 2026-09-29

The owner requested upgrading PostgreSQL after the pgvector upgrade. Upgraded
Proximal's managed `17/main` cluster on port 5432 from 17.10 to 17.11 and
activated it with one controlled restart. This is an operator-authorized change;
the daily update bot's database restrictions remain unchanged.

## Scope and preflight

- Exact packages: `postgresql-17` and `postgresql-client-17`, from
  `17.10-1.pgdg24.04+1` to `17.11-1.pgdg24.04+2`, through existing PGDG apt.
  Simulation and installation changed only those two packages. Holds retained.
- Read [upstream 17.11 release notes](https://www.postgresql.org/docs/17/release-17-11.html).
  No logical replication slots, `btree_gist`, or `ltree` extensions were present.
  `pgcrypto` is installed in several databases; a bounded source search in Engram,
  Hippo, BinKeeper, and Striatum found no PGP encryption/decryption call sites.
  This is not an exhaustive encrypted-data audit; no encrypted data was rewritten.
- No configuration parse errors, open client transactions, or prepared transactions
  at the activation gate. Package installation held automatic service stops/restarts
  with a temporary `policy-rc.d`; its removal was verified before activation.
- Maintenance held `/var/lib/update-bot/host.lock`. Downloaded both old and new
  server/client packages to retain a recovery option before installing.
- Fresh pgBackRest check and differential backup passed before installation:
  `20260927-010427F_20260929-083807D`, stanza `proximal`.

## Activation and checks

`systemctl restart postgresql@17-main.service` completed in 4.43 seconds. This is
command duration, not an independently measured availability interval. It performed
normal fast shutdown/startup, without an immediate/crash shutdown. The live server
reports `17.11 (Ubuntu 17.11-1.pgdg24.04+2)`.

The cluster system identifier remains `7652478211804703267`. All 20 connectable
databases (including `template1`) were checked, and their extension name/version
sets match the preflight snapshot. The five pgvector 0.8.6 databases and all retained
0.6.0 extensions are unchanged. Vector distance checks passed in all 17 databases
with vector installed (including `template1`). Nearest-neighbor queries against
existing Engram and Hippo data each returned five rows.

Durability settings (`fsync`, `full_page_writes`, `synchronous_commit`, `wal_level`),
archive mode, and preloaded libraries match the before snapshot. A post-restart
pgBackRest check passed, and WAL archiving advanced without a recorded failure.
Both PostgreSQL exporters report `pg_up 1` and scrape error 0.

Praxis, GPU-fleet, Plane, and the exporters reconnected. Praxis and the GPU heartbeat
service each automatically restarted once during the interruption and are active.
Engram's operator service stayed active. These checks establish database operation
and the observed reconnections, not a full end-to-end test of every application.
